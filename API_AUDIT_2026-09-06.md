# API audit — 2026-09-06

This alpha was statically cross-checked against the public `libxse/commonlibf4` headers available on 2026-09-06.

Verified interfaces used by the source:

- `TESObjectARMA::bipedModel[2]`, `bipedModel1stPerson[2]`, `skinTextures[2]`
- `TESObjectARMO::modelArray` and `ArmorAddon::armorAddon`
- `TESNPC::HeadRelatedData::faceDetails`
- `TESNPC::GetSex()`
- `TESRace::faceRelatedData[2]` and `FaceRelatedData::defaultFaceDetailsTextureSet`
- inherited `BGSSkinForm::formSkin` on both `TESNPC` and `TESRace`
- `TESForm::CreateDuplicateForm(...)` and `TESForm::SetTemporary()`
- `BGSTextureSet::textures[8]` and `textureFileIDs[8]`
- `BSResource::ID::GenerateFromPath(...)`
- `Actor::Reset3D(...)`
- F4SE messaging constants including pre/post save, pre/post load, new game, game loaded and game-data-ready

The project contains no custom executable offsets, no trampoline writes and no hand-authored relocation IDs.

## What this audit does not prove

It is not a substitute for compiling with MSVC/CommonLibF4 or running Fallout 4. In particular, the first binary test still needs to validate:

1. duplicate-form lifetime/ownership under long play sessions,
2. whether every target skin ARMA rebuilds exactly as expected after `Reset3D`,
3. LooksMenu/FaceGen behavior when the player face TXST is swapped before a reset,
4. save/load behavior across repeated saves and character changes,
5. runtime compatibility for the exact CommonLib/F4SE build selected.

The included `TEST_PLAN.md` is written around those risks.
